# MLView agent guide

## User ground rule

Every spawned subagent must explicitly use **Sol (`gpt-5.6-sol`)**, including
agents spawned by other agents. Do not substitute another model. This does not
change the parent agent's model.

## Active product

MLView is a skill using the active Copilot, Codex, or Claude Code model inside
VS Code as its interpretation and analysis backend. The user invokes the skill
in the native assistant, then opens its interactive diagram.

On 2026-09-18 the user explicitly requested removal of the old static analyzer.
It and its host integrations, CLI, rule catalog, Python distribution, MCP
services and static CI gates are removed. This supersedes earlier instructions
to preserve the legacy path. Do not reintroduce it or build a static semantic
fallback. Historical design documents and Claude sessions are evidence of past
work, not current requirements or authorization.

Read [README.md](README.md), [docs/WORKFLOW_CONTRACT.md](docs/WORKFLOW_CONTRACT.md),
[docs/LLM_WORKFLOW.md](docs/LLM_WORKFLOW.md), [docs/STATUS.md](docs/STATUS.md),
[CONTRIBUTING.md](CONTRIBUTING.md), and [docs/CODEX_HANDOFF.md](docs/CODEX_HANDOFF.md).

## Ownership and boundaries

- `skills/mlview/` is the canonical skill. Its helper validates and publishes
  model-authored documents; it does not interpret target programs.
- `contracts/workflow.schema.json` is the active artifact schema. Keep the accompanying contract in `docs/WORKFLOW_CONTRACT.md` and
  the skill quick reference consistent.
- `webview/src/` owns the interactive renderer. Its internal graph projection
  is a display representation, not a source analyzer.
- `vscode-extension/src/` owns workspace validation, panels, navigation and
  refinement prompts. Opening or filtering a diagram must not call a model.
- `claude-plugin/skills/mlview/` is generated by `tools/sync-skill.py`.
- `tools/sync-assets.py` copies the built viewer into the extension.
- Preserve immutable native evaluation outputs. Old citation paths resolve
  through `evals/workflow/fixtures/historical-paths.json` only in evaluation
  replay; the product must still validate real workspace paths normally.

## Verification

Use Python 3.10+ and Node 20.18.1+. Prefer a suitable checkout venv and put it on
PATH for subprocesses. Set `PYTHONDONTWRITEBYTECODE=1` during checks.

- `python -m pip install -r requirements-dev.txt`
- `sh scripts/e2e.sh` (Windows: `powershell -File scripts/e2e.ps1`)
- Focused suites: `python -m pytest skills/mlview/tests tools evals scripts claude-plugin/tests -q`;
  `npm run check && npm test` in either TypeScript component.
- `python tools/verify.py --all` verifies generated copies and native-only packaging.
- `python scripts/check_docs.py` checks current documentation.

Report commands actually run. Local tests do not prove live native-host use or
semantic correctness, and old CI runs do not validate new edits. Human review
of the evaluation ledgers remains pending unless the user provides it.

## Working history and git

Keep work on a feature branch; inspect branch ancestry before a new campaign.
Preserve unrelated working changes. Do not force-push or rewrite shared history.
If present, `.workflows/claude-history/README.md` indexes recovered conversations.
Keep raw transcripts, credentials and machine paths out of committed docs.
Update the handoff when active work changes. Frozen decision records should
remain historical rather than being rewritten to claim today's behavior.
