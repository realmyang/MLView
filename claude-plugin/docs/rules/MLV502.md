# MLV502 - Hard-coded CUDA device with no availability check

| | |
|---|---|
| **Severity** | `medium` - amber triangle - likely wrong, or right only under an assumption that cannot be checked statically |
| **Frameworks** | torch |
| **Base prior** | 0.85 |
| **Rule version** | 1 |
| **Tags** | `portability`, `device` |
| **Absence rule** | no |
| **Enabled** | yes |

## Why it matters

On any machine without a GPU - a laptop, a CI runner, a colleague's box - the very first tensor move raises, so the script is not runnable anywhere except the machine it was written on.

## How it is detected

A `torch.device("cuda")` written with a string literal at the call site, or a `.cuda()` call, in a workspace where nothing calls `torch.cuda.is_available()` (or any `*_is_available` / `device_count` probe).

## False positives it avoids

- `torch.device("cuda" if torch.cuda.is_available() else "cpu")` - the literal is there, and so is the guard.
- A device that arrives through a module constant or a config object, whose default this analyzer cannot see.
- Repetition: one finding per module, with the other sites as related locations.

## How to fix it

Use device = torch.device("cuda" if torch.cuda.is_available() else "cpu") and move the model and batches to that device.

## Example that fires

`analyzer/tests/fixtures/rules/MLV502_bad.py`

```python
"""The device is named outright and nothing in the workspace ever asks whether a
GPU exists, so the script raises on the first tensor move on any CPU-only box."""
import torch
import torch.nn as nn
import torch.optim as optim
from torch.utils.data import DataLoader, TensorDataset


def train(dataset: TensorDataset, epochs: int = 3) -> nn.Module:
    torch.manual_seed(0)
    model = nn.Sequential(nn.Linear(16, 3))
    device = torch.device("cuda")
    model.to(device)
    criterion = nn.CrossEntropyLoss()
    optimizer = optim.SGD(model.parameters(), lr=0.1)
    train_loader = DataLoader(dataset, batch_size=32, shuffle=True)

    model.train()
    for epoch in range(epochs):
        for features, labels in train_loader:
            features = features.to(device)
            labels = labels.to(device)
            optimizer.zero_grad(set_to_none=True)
            loss = criterion(model(features), labels)
            loss.backward()
            optimizer.step()
    return model
```

## Example that does not

`analyzer/tests/fixtures/rules/MLV502_good.py` - the nearest false-positive trap this rule has to survive.

```python
"""The trap: the literal string "cuda" is written on the very same line, but it
is the true branch of an availability check, which is the idiom the rule exists
to ask for. Matching the literal without reading the guard would fire here."""
import torch
import torch.nn as nn
import torch.optim as optim
from torch.utils.data import DataLoader, TensorDataset


def train(dataset: TensorDataset, epochs: int = 3) -> nn.Module:
    torch.manual_seed(0)
    model = nn.Sequential(nn.Linear(16, 3))
    device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
    model.to(device)
    criterion = nn.CrossEntropyLoss()
    optimizer = optim.SGD(model.parameters(), lr=0.1)
    train_loader = DataLoader(dataset, batch_size=32, shuffle=True)

    model.train()
    for epoch in range(epochs):
        for features, labels in train_loader:
            features = features.to(device)
            labels = labels.to(device)
            optimizer.zero_grad(set_to_none=True)
            loss = criterion(model(features), labels)
            loss.backward()
            optimizer.step()
    return model
```
