# MLV111 - Evaluation DataLoader shuffles

| | |
|---|---|
| **Severity** | `low` - blue circle - hygiene, reproducibility, portability, or a question worth asking |
| **Frameworks** | torch |
| **Base prior** | 0.90 |
| **Rule version** | 1 |
| **Tags** | `data`, `reproducibility` |
| **Absence rule** | no |
| **Enabled** | yes |

## Why it matters

Predictions no longer line up with the dataset order, so per-sample inspection and confusion matrices differ from run to run.

## How it is detected

A `DataLoader(...)` with the literal `shuffle=True` whose dataset carries `VAL_SPLIT` / `TEST_SPLIT`, or whose variable matches the evaluation naming convention.

## False positives it avoids

- Training loaders, which *should* shuffle.
- This is deliberately `low`: shuffled evaluation is legitimate when you are sampling examples to look at. The cost is per-sample alignment and reproducible confusion matrices, not correctness.

## How to fix it

Use shuffle=False on validation and test DataLoaders so predictions stay aligned with the dataset order.

## Structured fix

This rule opts into `Issue.fix` (H5, CONTRACTS 11.42). A host may offer **Set shuffle=False on this evaluation DataLoader** as a quick fix, graded `mechanical`. The edit is computed from the AST, it is **never applied automatically**, and no edit is offered at all when the finding lands below the `likely` confidence bucket.

- **Offered when** the `shuffle=` keyword is the literal `True` at the call site - the edit replaces that one literal and nothing else, so a trailing comment on the same line survives it.
- **Withheld when** `shuffle=` is a variable or an expression rather than a literal, so what the edit would have to say about it is not statically known.

## Example that fires

`analyzer/tests/fixtures/rules/MLV111_bad.py`

```python
"""The test loader shuffles, so predictions no longer match dataset order."""
import torch
from torch.utils.data import DataLoader, TensorDataset, random_split


def build(dataset: TensorDataset):
    train_ds, test_ds = random_split(dataset, [45000, 5000],
                                     generator=torch.Generator().manual_seed(0))
    train_loader = DataLoader(train_ds, batch_size=64, shuffle=True)
    test_loader = DataLoader(test_ds, batch_size=256, shuffle=True)
    return train_loader, test_loader
```

## Example that does not

`analyzer/tests/fixtures/rules/MLV111_good.py` - the nearest false-positive trap this rule has to survive.

```python
"""The trap: shuffle=True everywhere it belongs. The training loader shuffles
(and must not be mistaken for an evaluation loader just because it shuffles),
a generic `loader` over untagged data shuffles, and only the loaders over the
held-out split are ordered."""
import torch
from torch.utils.data import DataLoader, TensorDataset, random_split


def build(dataset: TensorDataset, extra: TensorDataset):
    train_ds, val_ds, test_ds = random_split(
        dataset, [40000, 5000, 5000], generator=torch.Generator().manual_seed(0))
    train_loader = DataLoader(train_ds, batch_size=64, shuffle=True)
    loader = DataLoader(extra, batch_size=64, shuffle=True)
    val_loader = DataLoader(val_ds, batch_size=256, shuffle=False)
    test_loader = DataLoader(test_ds, batch_size=256)
    return train_loader, loader, val_loader, test_loader
```
